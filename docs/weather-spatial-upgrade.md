# 气象、空间分析与统一视觉升级验收

## 新功能入口

- 左侧“打开位置天气 / 逐小时预报”：当前地面天气、24 个逐小时预报、时刻滑块、地图标记。先选机场或飞机可查询对应坐标，也可手动输入位置。
- 空间分析新增“方向扇区查询”，并提供飞机高度差 / 采集时间差筛选及归档航迹统计。
- 地图视觉语义集中在 `src/config/visualRules.js`；基础界面变量在 `src/styles.css`。二维、三维、机场资料库和图例使用相同机场符号。

## 架构和边界

`WeatherPanel.vue` 只展示数据，`useWeatherQuery.js` 管理请求与选择位置状态，Django `flight_api/weather.py` 负责固定官方上游、字段标准化、单位、UTC 时间及缓存。不存在用户自定义上游 URL，因此不能将代理用于访问任意地址。

天气接口超时为 8 秒、响应体最大 1 MB、坐标校验为有限数值及经纬度范围。新数据缓存 10 分钟；上游失败时可显示一小时内的旧缓存，但有效时间和获取时间不改写。匿名查询有基础限流，部署到多实例时需要共享缓存 / 网关限流；当前不是完备的互联网滥用防护方案。

只有用户打开天气工具或点击刷新时发起天气请求；改变位置、关闭工具或卸载时取消旧请求。即使旧请求不响应取消，也通过版本号防止覆盖新位置数据。滑块改变时不新增请求。

地面天气和飞机历史位置的时间不同，不应将它解释为当时的航空天气。数据来自模型，不是 METAR / SIGMET / 雷达危险天气判定。Open-Meteo 免费服务限非商业使用，见 [官方条款](https://open-meteo.com/en/terms)；变量含义见 [官方文档](https://open-meteo.com/en/docs)。

OpenWeatherMap 瓦片与位置天气是独立功能，二维与三维的叠加透明度参数均为 1。瓦片自身的透明像素、网络故障、Key 权限等仍由外部服务决定。本轮新增了错误提示，不能承诺外部瓦片始终可用。

分析继续使用统一的球面距离引擎。方向角以正北为 0°，扇区允许跨越 0°。高度 / 时间条件先筛选，再选择最近目标；缺失相应字段的飞机被排除并计数。不用于飞行安全决策。

## 已完成验证

- 前端 46 项自动测试通过，覆盖真实 Vue 模板、四种分析的机场等级规则、扇区方向、轨迹断点、筛选顺序、天气滑块、缺失 / 零值、请求失败重试、取消与晚返回。
- 后端 10 项测试通过，覆盖机场 / 轨迹接口以及天气坐标校验、UTC 时间、单位、缓存、旧数据回退、上游失败、异常响应和限流。
- 生产构建通过。
- 实际天气链路：通过本项目 Django 天气接口请求法兰克福机场公开坐标，返回 HTTP 200、Open-Meteo 当前天气和 24 个小时预报；第二次同位置查询缓存命中。未使用模拟响应完成这项验证。
- 未修改原始机场、航班数据库，没有新增 OpenSky 远程采集请求，没有补造航迹点。

## 尚未完成的实测

浏览器访问本地项目此前被保存的用户权限拒绝；已请求用户允许访问，未绕过限制。上述自动测试和真实接口验证不能替代浏览器触摸、拖动、弹窗叠放及三维 WebGL 实测。

授权后应实际验收：

1. 桌面 / 手机打开天气面板，选择机场、输入新坐标、查询、拖动预报滑块，确认地图标记及时间一致。
2. 查询中切换位置、关闭 / 重开面板；旧数据不得覆盖新位置，加载状态不得卡住。
3. 二维和三维切换天气叠加、关闭 / 重开、切换底图；错误状态不得由某个成功瓦片掩盖。
4. 四种空间分析切换、改变高度 / 时间条件、关闭 / 重开、取消飞机选择；地图与计数同步。
5. 手机滚动只影响面板正文，标题和关闭按钮可用；检查四种工具互斥与桌面重叠层级。

本轮未推送 GitHub 或更新 Render。发布前应完成上述浏览器验收，随后同步前后端一起部署，否则旧后端无法提供新天气接口。
